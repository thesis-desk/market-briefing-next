# 조사 요청

아래는 이 조사 묶음을 만들게 한 요청의 사본이다. 요청이 바뀌면 맨 아래 변경 이력에 적는다.

---

## 요청 (2026-11-23)

요청자가 이 자료를 어디에 쓰는지와 요청이 어디서 왔는지는 적지 않는다(`docs/areas/datasets.md` 의 규칙). 요청을 줄이면 이렇다.

- 칼럼 1편("중국 오픈웨이트 공포는 과하다")과 2편("값이 뒤집히는 물건은 따로 있다")은 사는 쪽에서 봤다 — 오픈웨이트가 클로즈드 모델의 어느 일을 얼마나 가져가는가.
- 이번에는 파는 쪽을 본다 — 오픈웨이트 추론 시장에서 돈이 어디에 남는가.
- 자료는 2026-12-03 까지 모으고 AWS re:Invent 2026(11/30~12/4)의 발표를 넣는다. 형태는 칼럼 3편이다.

## 조사 설계 (요청을 풀어 쓴 것 — AI 가 정리했고 요청자가 고칠 수 있다)

### 질문

오픈웨이트 추론을 파는 쪽에서 돈은 어디에 남는가.

오픈웨이트 추론의 물량은 빠르게 늘었다(OpenRouter 의 오픈웨이트 토큰, 추론 플랫폼들의 매출). 그러나 같은 모델을 누구나 내려받아 팔 수 있어 값이 빨리 내린다. 파는 쪽은 셋으로 나뉜다 — 공개 모델을 토큰 단위로 되파는 일(서버리스 API), 고객 데이터와 전용 용량을 묶어 파는 일(사후 학습·전용 배포), 그리고 같은 모델을 자기 클라우드 계약에 묶어 파는 하이퍼스케일러. 이 조사는 셋 가운데 어디에 마진이 남는지를 본다.

### 가설 셋

결론이 아니라 검정할 대상이다. 맞는 증거와 반대 증거를 같은 무게로 모은다.

- **H1. 공개 오픈 모델을 토큰 단위로 되파는 일(서버리스 API)은 범용품이 돼 마진이 얇다 — 같은 모델의 사업자 간 단가가 모이고, 단가가 원가보다 빨리 내린다.**
- **H2. 오픈웨이트 추론에서 돈이 남는 자리는 고객 데이터·전용 용량을 묶은 일(사후 학습, 전용 배포)이다 — 매출과 마진이 그쪽에 있고 그쪽으로 옮겨 간다.**
- **H3. 하이퍼스케일러(AWS·Google·Microsoft)가 오픈웨이트 추론을 자기 클라우드 계약에 묶어 팔면서 독립 추론 사업자의 자리를 좁힌다.**

셋을 나누는 이유: H1 이 맞아도 H2 는 틀릴 수 있다(토큰 재판매가 얇으면서 맞춤 사업도 얇을 수 있다 — 그러면 남는 곳은 GPU 를 가진 쪽이다). H2 가 맞아도 H3 이 맞으면 그 자리를 독립 사업자가 아니라 하이퍼스케일러가 가져간다.

### 묶음

| 묶음 | 파일 | 무엇을 모으나 |
| --- | --- | --- |
| P1 단가 | `prices.json` | 같은 오픈 모델을 사업자마다 얼마에 파는가, 그 추이, 물량이 싼 사업자로 가는가 |
| P2 원가 | `costs.json` | 칩·랙 세대별 100만 토큰당 서빙 원가, GPU 시간당 값, 원가 계산의 가정(가동률) |
| P3 사업자 손익 | `providers.json` | 추론 플랫폼의 매출과 증가율, 매출총이익률, 매출 구성(토큰 API·전용 배포·GPU 임대·사후 학습), 고객 집중, 전용 배포 가격 |
| P4 하이퍼스케일러 | `hyperscalers.json` | AWS·Google·Microsoft 의 오픈 모델 상품과 단가, 미세조정·전용 용량 상품, 경영진 발언, 독립 사업자와의 협력·경쟁 |
| P5 반대 증거 | `counter.json` | 토큰 재판매로 남기는 사례, 맞춤 사업이 안 되는 조건, 독립 사업자가 하이퍼스케일러를 이기는 값 |

### 지킬 것

- 기록마다 가설에 대한 방향(`sides`: 지지 · 반박 · 양쪽 · 중립)과 이유를 적는다. 방향은 AI 의 해석이다.
- 원문을 열어 읽은 값과 검색 요약만 본 값을 가른다. 기억으로 아는 값은 넣지 않는다.
- 사업자 숫자는 대부분 자기 보고나 투자자·정리 사이트의 추정이다. 누가 쟀는지와 이해관계를 `definition` 에 적는다.
- "무엇과 견준 값인가"를 적는다 — 같은 모델의 다른 사업자, 서버리스 대 전용 배포, 하이퍼스케일러 대 독립 사업자.
- 원가는 모델 크기와 사용자당 속도 조건에 따라 몇 배씩 달라진다. 조건을 `detail` 에 적고 범위로 쓴다.
- 특정 회사·사업자 입장의 시사점은 쓰지 않는다.

### 틀렸다고 볼 조건

- H1: 같은 모델의 사업자 간 단가 격차가 유지·확대되고 비싼 사업자가 물량을 잃지 않는다 / 토큰 API 중심 사업자가 매출총이익률 60% 이상을 낸다 / 토큰 단가 하락이 같은 기간 서빙 원가 하락보다 느리다.
- H2: 전용 배포·사후 학습 매출의 마진이 토큰 API 보다 높지 않다 / 그 매출이 소수 고객에 몰려 있다 / 사후 학습 채택이 멈추거나 랩·하이퍼스케일러가 같은 상품을 더 싸게 묶어 판다.
- H3: 하이퍼스케일러의 오픈 모델 단가가 독립 사업자보다 비싸고 물량도 독립 사업자 쪽으로 간다 / 하이퍼스케일러가 오픈 모델을 올린 뒤에도 독립 사업자의 매출이 빨라진다 / 하이퍼스케일러가 독립 사업자를 경쟁자가 아니라 협력사(마켓플레이스, 공동 판매)로 들인다.

### 순서

1. 데스크에 있는 기록으로 묶음을 연다 — 조사 `open-weight-substitution` 의 추론 시장·단가 기록, 가격 탭의 GPU 임대가, 자체 서빙 원가 계산.
2. 바깥 자료를 네 갈래로 모은다 — 단가(P1), 사업자 손익(P3), 하이퍼스케일러(P4), 원가와 반대 증거(P2·P5).
3. 값이 큰 기록의 원문을 다시 확인한다.
4. re:Invent 발표(행사 정리 `reinvent-2026` 이 모으는 자료와 AWS 원문)를 P4 에 더하고 가설을 판정한다(12/3).
5. 칼럼 3편.

### 칼럼 3편의 줄거리 (요청자 결정, 2026-11-23)

"전용 배포·사후 학습이 살길이다"라는 한 줄 대신 조건을 세운다. 판정(12/3) 뒤 문장은 바뀔 수 있다.

1. 1·2편 정리 — 오픈웨이트는 프론티어를 먹지 않고 좁은 일·대량 일을 가져간다.
2. 시장은 진짜고 값은 생각보다 버틴다 — 물량은 늘었고 같은 모델의 단가는 개발사 정가에 묶여 있다.
3. 남기는 것은 원가다 — 중심은 같은 세대 안에서 NVL72 랙과 8장 노드(HGX)의 원가 차이가 모델 크기·작업에 따라 어떻게 갈리는가다(요청자 지적: "칩 세대가 아니라 NVL72 냐 아니냐"). 곁들여 GPU 임대가 상승, 토큰 API 를 접은 회사들, 보유와 임대의 원가 차이.
4. 웃돈은 맞춤에 있지만 조건부다 — 웃돈은 엔지니어링에서 나오고 경쟁이 붙으면 임대가로 내려온다. 고객 집중과 일 나눠 맡기기.
5. 하이퍼스케일러는 경쟁자이면서 유통 채널이다 — re:Invent 발표로 고친다.

## 변경 이력

- 2026-11-23 처음 적음.
- 2026-11-23 요청자가 칼럼 3편의 줄거리를 조건 중심 5단으로 정했다.
