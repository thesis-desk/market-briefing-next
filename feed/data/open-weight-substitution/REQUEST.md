# 조사 요청

아래는 이 조사 묶음을 만들게 한 요청의 사본이다. 요청이 바뀌면 맨 아래 변경 이력에 적는다.

---

## 요청 (2026-11-20, 대화창에서 말한 그대로)

> 오늘 수집된 자료중에 투마로x 자료 중 파이어웍스가 있거든. 근데 그 사람의 말과 우리의 가설이 딱 맞아떨어지지는 않네.

칼럼("중국 오픈웨이트 공포는 과하다", 당시 가격 탭의 AI 모델 가격·성능 화면, 지금은 자체 분석 탭)을 고칠지 묻자:

> 칼럼은 놔두고 반론은 후속편 느낌으로 자료를 모아보자.

이어서:

> 법률 전문으로 유명한 하비같은 경우 이런 오픈웨이트 모델 기반 특화 모델이라고 할 수 있겠지? 자체모델이라기보다는 파인튜닝이라고 봐야되나? 아니면 그냥 gpt wrapper인가?

## 조사 설계 (요청을 풀어 쓴 것 — AI 가 정리했고 요청자가 고칠 수 있다)

### 질문

오픈웨이트는 클로즈드 모델의 어느 일을 얼마나 가져가는가.

칼럼은 "범용 오픈웨이트를 공개 API 가격으로 사서 범용 에이전트 과제를 시키면 과제당 더 싸지 않다"를 쟀다. Fireworks 대표가 말한 것은 다른 물건이다 — 고객의 일에 맞춰 사후 학습한 오픈웨이트를 전용 배포로 좁은 일에 쓰는 것. 후속편은 이 물건이 실제로 어디를 얼마나 먹는지를 다룬다.

### 가설 셋

결론이 아니라 검정할 대상이다. 맞는 증거와 반대 증거를 같은 무게로 모은다.

- **H1. 오픈웨이트가 물량을 가져가는 곳은 프론티어가 아니라 소형 클로즈드 계층(대량·반복 작업)이다.**
- **H2. 고객의 일에 맞춰 사후 학습한 오픈웨이트는 좁은 일에서 클로즈드 API 와 같은 품질을 몇 분의 1 비용으로 낸다.**
- **H3. 특화·전용 배포로 옮겨 가는 지출이 프론티어 랩의 기업 API 매출을 깎을 크기로 커지고 있다.**

셋을 나누는 이유: H2 가 맞아도(기술적으로 된다) H3 은 틀릴 수 있고(규모가 작다), H1 이 맞으면 "프론티어를 잡아먹는다"는 줄거리는 틀리면서도 프론티어 랩의 소형 모델 매출은 줄 수 있다. 칼럼의 결론은 H3 이 틀렸다는 쪽이고, Fireworks 대표의 말은 H2 가 맞다는 쪽이다.

### 묶음

| 묶음 | 파일 | 무엇을 모으나 |
| --- | --- | --- |
| W1 계층별 몫 | `tiers.json` | 프론티어·소형 클로즈드·오픈웨이트의 토큰 몫과 지출 몫, 단가의 시계열 |
| W2 특화 모델 사례 | `cases.json` | 이름이 나온 회사가 무엇을 무엇으로 옮겼고(기반 모델, 학습·서빙한 곳) 비용·품질을 어떻게 밝혔나 |
| W3 추론·사후 학습 시장 | `platforms.json` | 추론·사후 학습 플랫폼의 매출과 증가율, 맞춤 배포의 비중, 사후 학습 채택률 |
| W4 프론티어 랩의 노출과 대응 | `labs.json` | 소형 모델 가격의 내력, 랩의 미세조정·증류 상품, 계층별 매출과 위험요인 문구 |
| W5 반대 증거 | `counter.json` | 특화가 통하지 않은 조건, 도입 장벽과 유지 비용, 프론티어로 돌아간 사례, 중국 기반 모델 기피 |

### 지킬 것

- 가설에 맞는 증거만 모으지 않는다. 기록마다 가설에 대한 방향(`sides`: 지지 · 반박 · 양쪽 · 중립)과 그 이유를 적고, 묶음마다 방향별 건수를 센다. 방향은 AI 의 해석이다.
- 원문을 열어 읽은 값과 검색 요약만 본 값을 가른다. 기억으로 아는 값은 넣지 않는다.
- 사례의 수치는 대부분 파는 쪽(플랫폼)이나 만든 쪽(응용 회사)이 직접 잰 값이다. 누가 쟀는지와 이해관계를 `definition` 에 적는다.
- "무엇과 견준 값인가"를 적는다. 특화 모델을 기반 모델과 견준 값, 소형 클로즈드와 견준 값, 최상위 프론티어와 견준 값은 뜻이 다르다.
- 짧고 반복되는 일(추출·분류)과 긴 에이전트 과제를 가른다. 칼럼이 잰 것은 뒤쪽이다.
- 기반 모델의 국적을 적는다. "중국" 오픈웨이트인지가 원래 줄거리의 한 축이다.

### 틀렸다고 볼 조건

- H1: 프론티어 모델의 토큰·지출 몫이 내리기 시작한다 / 오픈웨이트 기반 모델이 긴 에이전트 과제(코딩 에이전트 등)의 지출에서 큰 몫을 가져간다.
- H2: 사례의 비용 절감이 기반 모델이나 소형 클로즈드와 견줄 때 사라진다 / 제3자가 잰 값이 회사가 밝힌 값과 크게 다르다 / 특화 모델을 접고 클로즈드로 돌아간 사례가 쌓인다.
- H3: 오픈소스의 지출 몫이 계속 내린다 / 사후 학습 채택률이 멈춘다 / 플랫폼 매출이 소수 고객에 몰려 있다.

### 순서

1. 직접 읽은 자료(Fireworks 대담, Menlo 보고서, Harvey 의 글, Anthropic 상장 서류, 데스크의 OpenRouter·Artificial Analysis 기록)로 다섯 묶음을 연다.
2. 바깥 자료를 세 갈래로 모은다 — 사례, 플랫폼과 몫, 랩의 대응.
3. 값이 큰 기록의 원문을 다시 확인하고 가설을 판정한다.
4. 후속편(칼럼 또는 리포트)의 형태는 판정 뒤에 요청자가 정한다.

## 변경 이력

- 2026-11-20 처음 적음.
- 2026-11-22 요청("후속편 3차 조사도 이어서 진행해줘")에 따라 3차를 마치고 가설을 판정했다. 칼럼이 자체 분석 탭으로 옮겨져 위치 표기를 고쳤다.
