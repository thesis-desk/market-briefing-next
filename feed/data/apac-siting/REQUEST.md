# 조사 요청

아래는 이 조사 묶음을 만들게 한 요청의 사본이다. 요청이 바뀌면 맨 아래 변경 이력에 적는다.

---

Research Desk 조사 요청 (2026-11-18)

—현재 데이터센터 업계 트렌드 파악
ㅡ 아시아·태평양 AI 컴퓨트 입지 비교: 한국은 권역 거점이 될 수 있나

이 글 전체가 네가 할 일이다. 먼저 끝까지 읽고, 맨 아래 "9. 처음 할 일"부터 시작해라.
지금 사이트의 화면·수집 규칙·feed 가운데 이 글이 말하지 않은 것은 그대로 둔다.
모르는 것은 추측하지 말고 feed/QUESTIONS.md 에 질문으로 남겨라.
가진 자료가 없다고 보고 처음부터 모은다.

========================================
1. 무엇을 왜 모으나
========================================
질문: 빅테크와 프런티어 AI 랩이 아시아·태평양에 컴퓨트 용량을 둘 때, 한국은 한국 안의 수요를 넘어 권역 거점이 될 수 있는가.

확인하려는 가설 두 개. 결론이 아니라 검정할 대상이다. 맞는 증거와 반대 증거를 같은 무게로 모아라.
  H1. 입지 조건만 보면 한국은 권역 거점이 되기 어렵다. 특히 국제 네트워크, 대용량 전력의 확보 속도, 배후 수요가 약하다.
  H2. 프런티어 랩이 미국 밖에 둔 용량은 입지 조건보다, 현지 파트너가 내놓은 묶음(자본, 전력과 부지, 고객 수요, 부품)을 따라갔다.

지킬 것
- 특정 회사·특정 사업자 입장의 시사점은 쓰지 않는다. 사실, 수치, 원문에서 바로 따라 나오는 해석까지만 쓴다.
- 한국에 유리한 재료와 불리한 재료를 따로 세지 말고, 같은 지표를 모든 나라에 똑같이 적용한다.
- 받아 가는 쪽의 이름·주소·내부 사정, 이 요청이 어디서 왔는지는 저장소·화면·feed 어디에도 적지 않는다(이 저장소는 공개다).

========================================
2. 공통 규칙
========================================
대상 나라: 한국, 일본, 싱가포르, 말레이시아, 호주, 인도, 대만.
도시 단위가 필요할 때: 서울(수도권), 도쿄·오사카, 싱가포르, 조호르, 시드니·멜버른, 뭄바이·첸나이·하이데라바드, 타이베이.
묶음 B(랩의 해외 용량)만 전 세계를 본다.

기간: 2023-01-01 부터 수집 시점까지. 추이가 필요한 값(전기요금 등)은 2019년부터.

기록 한 건의 공통 필드
  {"id": "...", "country": "KR|JP|SG|MY|AU|IN|TW|…", "city": "...",
   "value": 숫자 또는 null, "unit": "...", "asof": "YYYY-MM-DD 또는 YYYY",
   "basis": "값의 정의·기준(예: 개통 당시 설계, 업그레이드 후, 발표 목표, 계산)",
   "sources": [{"title": "...", "url": "...", "date": "...", "read": "full|partial|search_summary"}],
   "alt": [{"value": ..., "basis": "...", "url": "..."}],     // 출처끼리 다른 값
   "conf": "high|med|low", "note": "한국어 한두 문장"}

출처와 검증
- 우선순위: 회사·정부·규제기관 원문 → 제조사·사업자 보도자료 → 통신사·전문지 → 정리 사이트·위키.
- 원문을 열어 읽은 값만 "read":"full" 또는 "partial" 로 적는다. 검색 결과 요약만 본 값은 "search_summary" 로 적고 conf 를 high 로 주지 않는다.
- 묶음마다 합계의 80%를 차지하는 큰 값은 반드시 원문을 열어 확인한다.
- 출처끼리 값이 다르면 하나를 고르고 나머지를 alt 에 남긴다. 고른 이유를 note 에 적는다.
- 출처가 없는 값은 null 로 둔다. 기억으로 아는 값을 채우지 않는다. '쌍 수 × 쌍당 용량'처럼 계산한 값은 basis 를 "계산"으로 적고 입력을 note 에 남긴다.
- 유료 자료 본문은 싣지 않는다. 공개 보도자료·요약에 나온 수치만 쓴다.

표기
- 데이터센터·전력 용량은 IT 기준이 기본이다. IT 없이 수전만 공개된 값에만 "(수전)"을 붙이고, 수전을 IT 로 환산해 IT 처럼 쓰지 않는다. 기준을 모르면 "기준 불명".
- 금액은 발표 통화와 달러를 함께 적고, 환산에 쓴 환율과 날짜를 적는다.
- '최대', '목표', 양해각서(MoU) 단계의 숫자는 확정 계약과 구분해 표시한다.

========================================
3. 모을 묶음
========================================

A. 투자 발표 장부 — "실제로 어디에 지었나"
  단위: 발표 1건.
  대상 회사: AWS, Microsoft, Google, Oracle, Meta, OpenAI, Anthropic, xAI. 여기에 ByteDance·Alibaba·Tencent 등 중국 빅테크가 대상 나라에서 짓거나 빌린 용량도 넣는다.
  필드: company, country, region, announced(날짜), amount(통화·금액·달러 환산), period(몇 년에 걸친 금액인가),
        mw(값·기준), stage("발표|부지확보|착공|가동"), partners, what("리전 신설|리전 확장|전용 캠퍼스|임차"), supersedes(이전 발표를 포함·대체하면 그 id)
  출처: 회사 보도자료, 각국 정부·투자청 발표, 통신사 기사.
  주의:
  - 같은 돈을 다시 발표한 것(누적 재발표)을 두 번 세지 않는다. supersedes 로 잇는다.
  - 금액에 운영비·인건비가 섞였는지, 설비투자만인지 적는다.
  - 발표 뒤 취소·축소·지연된 건은 지우지 말고 stage 와 note 에 적는다.
  - 나라별 합계는 '확정·착공 이상'과 '발표 포함' 두 가지로 낸다.

B. 프런티어 랩의 해외 용량 건별 조사 — H2 를 가르는 묶음 (전 세계)
  단위: 계약·프로젝트 1건. 대상 랩: OpenAI, Anthropic, xAI, Google DeepMind(구글 본체 리전과 구분되는 건만), Meta, Mistral.
  필드: lab, country, site, announced, mw, stage("MoU|계약|착공|가동"), partners,
        package: {"capital": 근거 문장 또는 null, "power_site": …, "demand": …, "components": …},
          // 파트너가 내놓은 것. 자본(투자·대출·지분), 전력과 부지, 고객 수요(정부·기업의 구매 약속), 부품(칩·메모리 공급)
        lab_spend(랩 자신이 돈을 내는가, 얼마인가), siting_reason(랩·파트너가 밝힌 입지 이유 원문 인용), status_now(지금 실제 진행 상태)
  판정: 건마다 "묶음을 따라감 / 입지를 따라감 / 둘 다 / 판단 불가" 가운데 하나를 고르고 근거를 적는다.
        package 가 모두 null 인데도 간 건(입지만 보고 간 건)을 따로 모은다. H2 의 반례다.
  주의: 발표만 있고 진행이 없는 건이 많다. status_now 를 꼭 확인한다.

C. 네트워크
  C1. 해저케이블 목록: 대상 나라에 닿는 국제 케이블(두 나라 이상에 닿는 것). 이름, 개통 연도, 계획 여부, 육양지, 소유자.
      출처: TeleGeography Submarine Cable Map 의 공개 자료.
  C2. 케이블별 용량: 시스템 설계 용량(Tbps), 광섬유 쌍 수, 개통 당시 값과 업그레이드 뒤 값.
      출처: submarinenetworks.com 케이블 페이지, 제조사(NEC·ASN·SubCom·HMN)와 소유 통신사 보도자료.
  C3. 빅테크(Google·Meta·Microsoft·Amazon) 참여 형태: 단독 소유 / 컨소시엄 구성원 / 쌍 구매. 보유 쌍 수와, 그 쌍이 어느 육양지까지 들어가는지.
  C4. 도시별 접속 여건: PeeringDB 공개 자료에서 인터넷 교환점 수, 교환점별 참여 네트워크 수, 빅테크와 주요 CDN 의 접속 지점 수.
  C5. 도시 간 왕복 지연시간(ms): 공개 측정값. 대상 도시끼리, 그리고 미국 서해안까지.
  나라별로 낼 값: 케이블 수(개통 연대별), 설계 용량 합계, 빅테크가 참여한 케이블의 용량, 빅테크 단독 케이블의 용량, 2021년 이후 개통분, 계획분.
  주의:
  - 설계 용량은 시스템 전체 값이라 나라 몫이 아니다. 여러 나라에 닿는 케이블은 나라마다 전체가 잡힌다는 점을 밝힌다.
  - 목록과 케이블 페이지가 육양지·개통 상태를 다르게 적는 경우가 있다. 둘 다 적는다.
  - 국제 회선 임차료와 IP 트랜짓 단가는 공개 수치를 찾으면 넣되, 못 찾으면 "공개 수치 없음"으로 둔다.

D. 전력
  D1. 품질: 수용가당 연간 정전 시간과 횟수(SAIDI·SAIFI). 각국 규제기관·전력회사 연차 보고.
  D2. 가격: 대용량(특고압) 산업 고객의 kWh 당 요금, 2019년부터 연도별. 각국 요금표를 기준으로 하고 기본요금·연료비 조정 포함 여부를 적는다. 데이터센터 전용 요금제가 생긴 나라는 따로 적는다.
  D3. 확보: 새 대용량 수전을 받기까지의 기간과 제한 제도. 예: 계통 영향 평가, 지역별 신규 접속 제한, 데이터센터 용량 할당제, 승인 대기 물량(MW). 제도 원문과 시행일.
  D4. 발전소 옆 직접 공급(자가발전·구역 전기) 사례: 나라별 건수, MW, 연료, 단계.
  D5. 전원 구성과 재생에너지 비중, 기업용 전력구매계약(PPA)·인증서의 가격과 체결 물량. 청정 전력은 따로 채점하지 않고 가격 묶음의 한 줄로만 쓴다.
  주의: 나라마다 정의가 다르다. 같은 기준으로 맞추지 못한 값은 맞추지 못했다고 적고 억지로 비교하지 않는다.

E. 배후 수요
  E1. 인구, GDP, 1인당 GDP(World Bank·IMF).
  E2. 도시별 데이터센터 시장: 운영·건설 중·계획 MW, 공실률, 임대료. CBRE·Cushman & Wakefield·JLL·Knight Frank 등의 공개 보고서.
  E3. 나라별 클라우드(IaaS·PaaS) 시장 규모와 성장률: 시장조사 회사가 공개한 수치만.
  E4. 나라별 AI 사용 지표: 랩이 공개한 국가별 사용 통계, 유료 구독자 순위, 기업 도입 발표.
  E5. 지연시간권: 서울·도쿄·싱가포르에서 왕복 50ms, 100ms 안에 닿는 나라의 인구와 GDP 합(C5 로 계산, 식과 입력을 남긴다). 수출통제나 데이터 규제로 서비스할 수 없는 시장은 뺀 값과 넣은 값을 함께 낸다.

F. 나머지 조건 (채점표 재료)
  F1. 재난: 지진·태풍·홍수 위험 지수(국제 지수 두 개 이상), 최근 10년 대형 데이터센터 피해 사례.
  F2. 인력: AI 인재 밀도와 개발자 수(Stanford AI Index, GitHub 통계 등), 데이터센터 건설·운영 인력 부족을 다룬 공개 조사, 임금 수준.
  F3. 제도: 법치·규제 품질 지수(World Bank WGI), 개인정보·데이터 국외 이전 규제, 공공·금융 부문의 국내 처리 요구와 클라우드 인증 제도, 데이터센터 인허가에 걸리는 기간.
  F4. 지정학: 미국 수출통제에서 나라별 지위(최신 규칙 원문 기준), 분쟁 위험을 다룬 공개 평가.
  F5. 인센티브와 비용: 데이터센터·AI 인프라에 대한 세액공제·보조금·부지 지원, 도시별 건설 단가(공개 지수).
  F6. 기후와 용수: 냉각에 영향을 주는 기온·습도 지표, 용수 제한 사례.

G. 한국 쪽이 내놓을 수 있는 것 (공개 사실만)
  G1. 메모리: HBM·D램 점유율, 한국 메모리 회사와 랩·빅테크 사이의 공급 계약·의향서 발표, 메모리 가격 추이.
  G2. 한국 기업과 랩 사이의 공개된 관계: 유통·재판매 파트너 발표, 대규모 도입 발표, 합작·투자.
  G3. 국내 준비 상태: 사업자별 데이터센터 계획 MW 와 가동 가능 시점, 정부의 AI 컴퓨팅 사업, 관련 법·특구 제도.
  같은 항목을 일본·대만·인도에도 적용해 견줄 수 있게 한다(예: 일본의 통신·금융 그룹, 대만의 파운드리·서버 제조사).

H. 반례와 경쟁 입지의 제약
  따로 모으지 않는다. A~G 에서 나온 것 가운데 H1·H2 에 어긋나는 사실, 그리고 일본·싱가포르·말레이시아 등의 제약(전력 한도, 건설비, 인력, 규제 변화)을 추려 한 파일로 정리한다.

========================================
4. 내보내기 (feed/data/apac-siting/)
========================================
사이트 빌드 때 함께 만든다. 기존 feed 파일의 필드는 바꾸지 않는다.

  feed/data/apac-siting/index.json         묶음별 상태와 파일 목록(가장 먼저 읽히는 파일)
  feed/data/apac-siting/investments.json   A
  feed/data/apac-siting/lab_overseas.json  B
  feed/data/apac-siting/cables.json        C1~C3 (케이블 1건이 한 항목, 나라별 합계는 "by_country" 에)
  feed/data/apac-siting/peering.json       C4·C5
  feed/data/apac-siting/power.json         D
  feed/data/apac-siting/demand.json        E
  feed/data/apac-siting/conditions.json    F
  feed/data/apac-siting/korea_package.json G
  feed/data/apac-siting/counter.json       H
