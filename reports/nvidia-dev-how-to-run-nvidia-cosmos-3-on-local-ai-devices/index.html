NVIDIA Technical Blog : Cosmos 3 Nano는 가중치를 시스템 RAM에 두면 12GB RTX에서도 돌아간다

해석 엔비디아가 월드 파운데이션 모델 Cosmos 3 Nano를 12GB VRAM의 RTX 5070에서 돌리는 방법을 공개했다. 대가는 128GB급 시스템 RAM과 720p 8초 남짓한 영상 하나에 40분이 넘는 생성 시간이다. 물리 AI 개발자의 입문 문턱을 소비자용 RTX까지 낮추는 생태계 조치로 보며, 엔비디아 실적에 미칠 영향은 작다고 판단한다.

주장 한 줄

사실

Cosmos 3 Nano는 가중치 대부분을 시스템 RAM에 두고 필요한 트랜스포머 블록만 GPU로 옮기는 방식(Cosmos-Framework 오프로딩 패키지)을 쓰면 VRAM 12GB GPU에서도 돌아가며, 공식 Hugging Face Diffusers 파이프라인 하나로 일곱 가지 생성 모드를 쓸 수 있다는 튜토리얼이다. 필자 두 명은 모두 엔비디아 엔지니어다.

출처 1 · 도입부, About the Authors

해석

새로 나온 것은 모델이 아니라 '12GB 소비자용 카드에서 일단 돌아간다'는 진입 경로다. 속도는 대화형과 거리가 멀고 호스트 RAM 요구가 크다. 그래서 이 글은 성능 발표가 아니라 개발자 저변을 넓히는 조치로 읽는 것이 맞다고 본다.

12GB 카드에서 돌아가는 대가는 시스템 RAM과 PCIe가 치른다

사실
  • 지금 쓰지 않는 가중치는 BF16 또는 체크포인트의 FP8 표현 그대로 시스템 RAM에 남고, 다음 트랜스포머 블록만 필요할 때 GPU로 옮긴다. 행렬곱과 어텐션 연산은 모두 CUDA에서 돈다.
  • 시스템 RAM이 가중치의 백킹 스토어다. 빠른 SSD는 모델 로딩에, 충분한 시스템 RAM과 PCIe 대역폭은 생성 중에 중요하다.
  • 시험한 소비자용 GPU 호스트는 모두 시스템 RAM이 약 128GB였다. 원문은 이것이 측정된 최소치가 아니라고 밝힌다.
  • 실행 환경은 Linux, Python 3.12, CUDA 지원 PyTorch다.

출처 1 · 도입부

해석

VRAM 요구를 낮춘 만큼 호스트 쪽 요구가 커졌다. 128GB는 최소치가 아니라고 했지만, 원문은 더 적은 RAM에서 측정한 결과를 하나도 내놓지 않았다. 12GB 카드를 가진 일반 사용자 PC가 실제로 감당할 수 있는지는 답하지 않은 질문이다.

모델 구조를 이용해 GPU로 옮기는 양을 줄인다

사실
  • Cosmos 3의 트랜스포머에는 프롬프트·조건 입력을 해석하는 이해(understanding) 경로와, 매 디노이징 스텝마다 영상·소리·행동 표현을 갱신하는 생성 경로가 함께 들어 있다.
  • 조건 입력과 정밀도가 고정되면 이해 경로는 한 번만 돌리고 그 결과를 디노이징 내내 재사용한다. 네이티브 FP8에서 디노이징 도중 정밀도가 바뀌면 이 컨텍스트를 다시 계산한다.
  • 35스텝 요청은 스텝마다 블록 0~35, 즉 36개 블록을 지난다(요청당 1,260회).
  • Classifier-free guidance의 조건부·비조건부 예측은 같은 블록을 공유하므로 분기마다 가중치를 다시 옮기지 않는다.
  • GPU에 여유가 있으면 현재 블록을 계산하는 동안 다음 블록을 옮긴다. 큰 작업은 자동으로 더 안전한 저메모리 스케줄로 바뀌며, 사용자가 설정할 전송 스케줄은 없다.
  • VAE 디코드와 안전 검사는 디노이징과 메모리 특성이 달라 따로 관리한다. 메모리가 빠듯한 카드에서는 메모리 효율적인 VAE 실행을 자동으로 쓴다.
  • Transfer(제어 영상 기반 생성)는 T2V·I2V보다 guidance 연산이 많다. 12GB GPU에서 720p로 돌리면 자동으로 저메모리 실행 모드를 고른다.

출처 1 · Reuse understanding context during generation, Manage memory across the complete request

해석

범용 오프로딩(Diffusers의 순차·모델·그룹 단위 오프로딩) 위에 Cosmos 구조에 맞춘 재사용 로직을 얹은 것이 핵심이다. 반대로 말하면 이 최적화는 Cosmos 전용이어서 다른 영상 모델에 그대로 옮겨 쓰기는 어렵다고 본다(확신 중간).

공식 Diffusers 파이프라인 하나로 일곱 가지 출력을 낸다

사실
  • 생성 모드는 일곱 가지다: 텍스트→영상, 이미지→영상, 영상→영상, 텍스트→영상+소리, 이미지→영상+소리, 행동(action) 생성, 제어 영상 기반 생성(Transfer, 예시는 에지 맵).
  • 프롬프트 처리, 조건·latent 준비, 디노이징 루프와 UniPC 스케줄러, CFG 출력 처리, VAE 디코드, 안전 검사, 출력 변환은 모두 공식 Diffusers 모듈형 파이프라인을 그대로 쓴다.
  • 행동 생성 예시는 'bridge_orig_lerobot' 도메인과 policy 모드, chunk 16, 1인칭 시점 입력 영상을 쓴다.
  • 안전 검사는 기본으로 켜져 있다.

FP8 체크포인트는 메모리를 더 줄이지만 파이프라인 전체가 FP8은 아니다

사실
  • FP8 체크포인트는 같은 저장소의 fp8 브랜치에 있고 NVIDIA Model Optimizer를 추가로 설치해야 한다.
  • 시험한 Nano 영상 체크포인트는 처음 세 스텝과 마지막 세 스텝에 W8A16(8비트 가중치를 역양자화하고 16비트 활성값 사용), 중간 스텝에 W8A8을 쓴다.
  • 어텐션은 BF16 SDPA로 남는다.
  • AI 생성 요약에 따르면 FP8은 최대 GPU 메모리를 줄인다. 절감 폭은 표(그림)에만 있어 확인하지 못했다.

속도는 실험용 수준이고 측정은 통제된 비교가 아니다

사실
  • 측정 GPU는 GeForce RTX 5070(12GB), 5080, 4090, 5090이다. 텍스트→영상은 네 카드 모두에서, 일곱 모드 전체는 RTX 5070에서만 측정했다.
  • RTX 5070은 BF16으로 720p 텍스트→영상을 2,624.9초(약 44분)에 끝냈고 최대 GPU 메모리는 9.94GiB였다. 이 수치는 본문 글자로는 AI 생성 요약에만 있고, 원 표는 그림이라 확인하지 못했다.
  • 파이프라인 시간에는 프롬프트 처리, 이해 경로, 디노이징, VAE 디코드, 안전 검사가 들어가고 체크포인트 로딩과 MP4 인코딩은 빠진다.
  • 영상·소리 모드는 189프레임·35스텝, Transfer는 121프레임·30fps, Action은 17프레임·30스텝이다. Action의 720p 등급은 실제로 640×480을 출력한다.
  • Transfer 행은 가드레일(안전 검사)을 끈 채 측정했다. 다른 행은 프롬프트·출력 안전 검사를 켜고 측정했다.
  • 모두 1회 측정이다. 원문 스스로 통제된 GPU 순위도, 여러 시드로 BF16과 FP8을 비교한 것도 아니라고 밝힌다.
  • 권장 시작 해상도는 GPU 메모리별 표(그림)로 제시됐고, 12GB GPU에서 빠르게 반복하려면 480p(848×480)나 240p(432×240)로 낮추라고 권한다.

해석

영상 1초에 5분 반이 걸리므로 반복 실험 도구로도 느리다. 원문이 시작 해상도로 240p·480p를 권하는 것도 같은 이유다. 5080·4090·5090의 시간은 그림에 있어 확인하지 못했다. 따라서 카드 등급이 올라갈 때 시간이 얼마나 줄어드는지는 이 리포트에서 판단하지 않는다.

근거는 어디서 왔나

설명
  • 근거는 모두 엔비디아의 자체 측정이다. 다만 패키지(GitHub cosmos-framework), 체크포인트(Hugging Face), 벤치마크 스크립트(benchmark_bf16.py·benchmark_fp8.py, 고정 입력과 사례별 로그 포함)가 공개돼 있어 독자가 다시 측정해 볼 수 있다.
  • 글쓴이만 가진 근거는 없다. 다만 수치 대부분이 그림 속 표에 있고, 본문 글자로 확인되는 값은 Nemotron이 만든 AI 요약의 RTX 5070 한 줄뿐이다. 페이지도 그 요약이 불완전할 수 있다고 고지한다.
  • Transfer 시간을 재현하려면 가드레일을 끄는 별도 옵션(--transfer-without-guardrails)이 필요하다. 따라서 Transfer 수치는 기본 설정의 체감 시간보다 낙관적일 수 있다.

원문이 지목한 하드웨어와 소프트웨어

사실
  • 대상 하드웨어는 GeForce RTX 5070·5080·4090·5090이고, 마무리에서 RTX GPU로 Cosmos 3 Nano 실험을 시작하라고 권한다.
  • 생성 성능을 좌우하는 호스트 요소로 시스템 RAM 용량과 PCIe 대역폭을, 로딩 속도 요소로 빠른 SSD를 든다.
  • 소프트웨어 경로는 Hugging Face Diffusers와 Hub, CUDA PyTorch, NVIDIA Model Optimizer다.
  • 경쟁 GPU나 CUDA 밖의 실행 환경은 언급하지 않는다.

출처 1 · Step 2, Step 4, Get started with Cosmos 3 Nano on GeForce RTX GPUs

비판적으로 다시 읽기

해석
  • 말하는 자리: 필자는 Cosmos와 RTX를 만드는 회사의 엔지니어이고, 글의 목적은 자사 모델과 소비자용 GPU로의 유입이다. 벤치마크의 한계(1회 측정, 통제되지 않은 비교)는 원문이 스스로 밝혔으므로 과장은 크지 않다.
  • '12GB면 된다'는 문구는 128GB급 호스트를 전제로 한다. 더 적은 RAM에서 측정한 결과가 없는 한 12GB는 GPU 쪽 하한일 뿐이고 시스템 전체의 하한으로 읽으면 안 된다.
  • 빠진 비교: VRAM이 넉넉한 데이터센터 GPU나 클라우드 인스턴스에서 같은 작업을 할 때의 시간과 비용, 그리고 오프로딩 없이 돌릴 때와의 속도 차이를 제시하지 않는다. 로컬 실행이 실제로 유리한 경우가 언제인지 판단할 근거가 없다.
  • FP8의 화질 영향은 다루지 않는다. 출력 검사도 해상도·프레임 수·fps 같은 형식 확인에 그친다.

덧붙임 · 투자자 관점 여기까지가 누구의 관점도 넣지 않은 공통 본문입니다. 아래는 밸류에이션과 투자 판단을 담은 덧붙임이며, 해석과 가정이 중심입니다.

투자자 관점의 정리

해석
  • 확인된 것: 엔비디아는 물리 AI용 월드 모델을 데이터센터 밖 소비자용 RTX(12GB급)까지 끌어내려 개발자 입문 경로를 만들고 있다. 경로는 CUDA·Diffusers·Hugging Face로 이어지는 자사 중심 스택이다(확신 높음).
  • 새로 나온 것: 성능 개선이 아니라 메모리 제약을 시간과 호스트 RAM으로 맞바꾸는 실행 방식이다. 720p 영상 1초에 약 5분 반이 걸리므로 상용 추론 경로를 대체하지 못하고 실험·학습용에 머문다고 본다(확신 높음).
  • 답하지 않은 것: 최소 시스템 RAM, 상위 카드에서의 단축 폭(그림이라 미확인), FP8의 품질 손실, 클라우드 대비 비용이다. 이 가운데 하나라도 유리하게 확인되면 소비자 GPU가 물리 AI 개발용으로 쓰일 여지가 커진다.
  • 실적 추정에 미치는 뜻: 튜토리얼 하나로 GeForce나 데이터센터 매출 전제를 바꿀 근거는 없다. 밸류에이션 전제에서는 '물리 AI 생태계 장악'이라는 질적 논거를 조금 보강하는 정도다(확신 중간).
  • 다음에 확인할 것: Cosmos-Framework 저장소의 활동량(이슈·포크)과 Hugging Face 체크포인트 내려받기 추이, 128GB보다 적은 RAM에서의 커뮤니티 측정, 다른 영상·월드 모델이 같은 오프로딩 패키지를 쓰기 시작하는지.
  • NVIDIA — 호재, 강도 약함(확신 중간). 근거: 소비자용 RTX로 물리 AI 개발 입문 경로를 열어 CUDA·Cosmos 생태계를 넓힌다. 다만 속도상 상용 수요로 이어질 근거는 원문에 없다. 판정을 바꾸는 조건: 저장소·체크포인트 채택이 늘지 않거나, 같은 일을 클라우드에서 더 싸고 빠르게 할 수 있다는 것이 확인되면 중립으로 내린다.
  • DRAM 공급사 — 판정하지 않음. 128GB급 호스트 RAM이 쓰였지만 측정된 최소치가 아니고, 수요 규모를 가늠할 수치가 원문에 없다. 공급사를 나눠 볼 근거도 없다.
  • Hugging Face(비상장) — 배포 채널로서 질적으로 우호적이다. 투자 판정 대상은 아니다.
  • AMD 등 경쟁 GPU — 원문이 다루지 않아 판정 근거가 없다. 경로가 CUDA 전용이라는 점만 확인된다.
