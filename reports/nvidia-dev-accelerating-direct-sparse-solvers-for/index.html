NVIDIA Technical Blog : cuDSS 1.0으로 CAE·EDA의 희소 직접 해법을 단일 GPU에서 정식 운용할 수 있다

해석 cuDSS 1.0의 새 내용은 대칭 부정치 행렬의 정확도를 높이는 기본값 변경, 고정(pinned) 메모리 처리기, 기호 분해 가속이다. 처리 단계별 2.5~151배 가속과 약 30% 메모리 절감은 상당 부분 이전 버전에서 쌓인 성과다. 모두 NVIDIA가 직접 측정한 결과이고, MKL 대비 끝단(end-to-end) 가속은 제시되지 않았다. NVIDIA에는 CAE·EDA에서 CPU 해법을 대체할 근거가 하나 더 쌓인 약한 호재로 보지만, 종목 판단을 바꿀 자료는 아니다.

주장 한 줄

사실

cuDSS 1.0은 CPU 해법보다 빠르고, 까다로운 대칭 부정치 행렬에서도 정확하며, GPU와 CPU 메모리를 함께 써서 이전에 여러 GPU가 필요하던 문제를 GPU 한 장으로 푸는 상용 수준의 희소 직접 해법 라이브러리라는 것이 글의 주장이다. 글은 그 근거를 정확도 기법, CPU 해법 대비 성능, 시스템 수준 최적화의 세 축으로 정리한다.

출처 1 · 도입부; Get started with cuDSS

  • 대칭 행렬에서 대칭을 보존하는 매칭·스케일링(HSL MC64)과 Bunch-Kaufman 피벗팅이 기본으로 켜진다. 비대칭 행렬에도 매칭·스케일링이 기본으로 켜진다.
  • 선택해서 쓰는(opt-in) 고정 메모리 처리기 cudssSetPinnedMemHandler()가 추가됐다.
  • GPU 기호 분해가 0.8.0보다 2.21배 빨라졌다(기하평균).
  • 하이브리드 실행 모드와 하이브리드 메모리 모드를 지원 구성에서 함께 켤 수 있게 됐다.

출처 1 · Enhancing accuracy for symmetric matrices; Pinned memory handler; Symbolic factorization improvements

해석

1.0에서 정말 새로 생긴 것은 위 네 가지다. 글 앞부분의 MKL 대비 가속과 약 30% 메모리 절감은 0.4~0.8 버전에서 쌓인 성과를 1.0 시점에 모아 보여 준 성격이 강하다. 메모리 절감은 캡션 스스로 대부분이 0.8.0에서 도입됐다고 밝힌다. 따라서 이번 글은 성능 도약 발표라기보다 기본 설정과 운용성을 상용 수준으로 다듬었다는 발표로 읽는 편이 맞다.

CPU 해법보다 단계별로 2.5~151배 빠르다(기하평균, 자체 측정)

사실
  • Intel MKL 2026.1.0 대비 cuDSS 1.0의 기하평균 가속은 분석(재정렬+기호 분해) 2.5배, 수치 분해 5.9배, 삼각 해법(solve) 151배다.
  • 측정 환경은 GPU NVIDIA B200(192GB HBM3e) 대 CPU Intel Xeon Platinum 8570이다. 결과는 같은 행렬에서 MKL 대비 성능이며, 행렬을 내보낸 업체끼리 비교한 것이 아니라고 밝힌다.
  • 벤치마크 행렬은 반도체 설계·제조와 CAE 흐름(회로 시뮬레이션, TCAD, 열, 구조, 전자기, 유체)에서 골랐고 희소 패턴·조건수·규모가 다양하다고 설명한다.
  • 실제 애플리케이션은 세 단계를 모두 거치므로 전체 가속은 단계별 비중에 따라 달라진다고 글 스스로 단서를 단다.

출처 1 · Enabling best performance for key computational engineering applications

  • 버전별 개선 이력은 0.4.0 슈퍼패널 분해, 0.5.0 다중 스레드 분석(재정렬), 0.8.0 solve 단계 커널 튜닝, 1.0 기호 분해 가속 등 표적 최적화다.
  • 그림 4·5는 v0.3.0 대비 버전별 가속을 두 행렬로 보여 준다. 하나는 Synopsys PrimeSim에서 내보낸 nv-sram, 다른 하나는 VLSI 22M 예제이며 둘 다 GPU 한 장 기준이다(배수 값은 확인하지 못함).

해석

가장 큰 숫자인 151배는 삼각 해법 단계의 값이다. 직접 해법에서는 보통 수치 분해가 시간을 가장 많이 쓰므로, 같은 분해를 여러 우변 벡터에 반복해 쓰는 흐름이 아니라면 체감 가속은 5.9배 쪽에 가까울 가능성이 크다. 글은 단계별 시간 비중도 끝단 가속도 내놓지 않아 사용자가 얻는 전체 효과는 이 글만으로 추정할 수 없다.

'업그레이드만으로'라는 말은 성능 개선에는 맞을 수 있다. 다만 같은 1.0에서 매칭과 피벗팅의 기본값이 바뀌었으므로, 업그레이드만으로 분해 구조·메모리·결과가 바뀔 수 있다는 점과는 긴장이 있다(다음 절).

대칭 부정치 행렬의 정확도를 기본 설정 변경으로 끌어올렸다

사실
  • 대칭 부정치 행렬은 최적 조류계산(optimal power flow), 유체·다공질 매체의 혼합 유한요소 이산화, PDE 제약 최적화, 구조 문제의 내부 모드 계산에서 나온다. 안장점(saddle-point)·KKT 행렬이 대표 사례다.
  • 이전에는 매칭이 대칭을 보존하지 못해 메모리·성능을 해쳤기 때문에 기본으로 꺼져 있었다. 이제는 대칭을 보존하며 기본으로 켜진다. 채움(fill-in)이 늘면 분석 이후 단계에 부담이 생길 수 있고, CUDSS_CONFIG_FORCE_NONSYMMETRIC_MATCHING으로 이전 동작을 되돌릴 수 있다.
  • 이전 cuDSS는 대각 피벗팅에 작은 피벗을 섭동(perturbation)으로 바꾸는 방식을 써서 안장점 행렬 다수에서 정확도를 잃었다.
  • Bunch-Kaufman은 2×2 피벗을 허용해 대칭을 보존하면서 분해를 안정시킨다. 문턱값은 CUDSS_CONFIG_PIVOT_THRESHOLD로 바꿀 수 있고, 값을 낮추면 1×1 피벗이 늘어 인자가 희소해지는 대신 정확도가 떨어진다.
  • 매칭 사이클을 1×1/2×2 후보 묶음으로 나누고 재정렬이 이 묶음을 인접하게 유지하므로, 채움을 줄이는 순서를 깨지 않고 2×2 블록을 찾는다고 설명한다. CUDSS_PIVOT_AUTO는 지원되는 경우 대칭·에르미트 부정치 행렬에 Bunch-Kaufman을 고른다.

출처 1 · Enhancing accuracy for symmetric matrices

  • 표 1은 SuiteSparse 공개 행렬에서 '매칭 없음+대각 피벗팅'과 '매칭·스케일링+Bunch-Kaufman(현재 기본값)'을 비교한다. 우변 b는 모두 1인 벡터이고, 상대 잔차·NRBE(노름 기준 상대 후방 오차)·섭동 피벗 수를 보고한다.
  • 결과는 NRBE 기준 최대 10자릿수(10 orders of magnitude) 정확도 개선과 섭동 피벗의 큰 감소다.
  • 시험 환경은 cuDSS 1.0, CTK13, RTX PRO 1000 Blackwell, Ubuntu 24.04.4 LTS다.
  • 표 2는 비대칭 행렬 중 매칭을 켜서 개선되는 SuiteSparse 행렬을 보여 준다. 매칭·스케일링이 정확도를 오히려 떨어뜨리는 경우도 몇 있으며, 이때는 CUDSS_MATCHING_ALG_NONE으로 끌 수 있다고 적었다.

출처 1 · Enhancing accuracy for symmetric matrices; Table 1·2

해석

정확도 결과에는 두 가지 한계가 있다. 첫째, 최대 10자릿수는 고른 행렬에서의 최댓값이다. 표 2는 글 스스로 '개선되는 행렬'을 보여 준다고 밝히므로 선택된 표본이다. 둘째, 정확도 시험은 B200이 아니라 워크스테이션급 RTX PRO 1000에서 돌렸고, 매칭으로 늘어난 채움이 성능·메모리에 준 영향은 수치로 나오지 않는다.

그래도 사업적 의미는 있다. 안장점·KKT 계열처럼 대각 피벗팅이 약하던 대칭 부정치 행렬에서 섭동 피벗이 크게 줄고 정확도가 오른다는 점이 중요하다. 내부점법 같은 최적화 해법과 전력망 최적 조류계산처럼 GPU 직접 해법의 신뢰성이 걸림돌이던 분야로 쓰임새가 넓어질 수 있다(확신 중간). 성능 가속보다 이쪽이 상용 채택에 더 중요한 변화일 수 있다.

CPU 메모리를 GPU 메모리의 연장으로 써서 단일 GPU로 푸는 문제를 키웠다

사실
  • 하이브리드 메모리 모드는 GPU HBM과 CPU DRAM에 데이터를 나눠 둔다. 연산 부하가 큰 분해·해법 커널은 GPU에 두고, 당장 필요 없는 데이터는 CPU 메모리로 내린다. 서버 노드의 CPU 메모리는 흔히 512GB~2TB라고 적었다.
  • 그 결과 시뮬레이션을 GPU에 맞는 작은 하위 영역으로 쪼개거나 여러 GPU를 쓸 필요 없이 전체를 한 시스템으로 풀 수 있다고 주장한다.
  • 대표적인 대형 VLSI 사례에서 최소 메모리 요구량이 0.7.1 대비 평균 약 30% 줄었다. 그림 캡션은 최적화 대부분이 0.8.0에서 들어왔다고 밝힌다.
  • 이전에 여러 GPU가 필요하던 문제를 H100, B200, Vera Rubin 한 장으로 풀 수 있어 배포가 단순해지고 계산 비용이 준다고 주장한다.
  • 분석 단계 뒤에 CUDSS_DATA_HYBRID_DEVICE_MEMORY_MIN으로 최소 장치 메모리를, CUDSS_DATA_MEMORY_ESTIMATES로 상시·최대 장치 메모리와 하이브리드 모드의 최소 장치·최대 호스트 메모리를 조회할 수 있다. 한도는 CUDSS_CONFIG_HYBRID_DEVICE_MEMORY_LIMIT로 정한다.

하이브리드 메모리 모드는 cuDSS의 핵심 설계 철학, 즉 GPU와 CPU가 함께 연산 플랫폼이라는 생각을 반영한다.

출처 1 · Hybrid execution paradigm

사실
  • 하이브리드 메모리 모드는 인자 값을 담은 전체 버퍼를 호스트에 둔다. 이전에는 할당 뒤 cudaHostRegister()로 고정(pinned)했는데, 이 등록 비용이 커서 대형 시스템에서는 등록을 끄는 편이 빠를 때도 있었다.
  • 1.0의 cudssSetPinnedMemHandler()는 고정 호스트 메모리용 사용자 할당기를 넣게 해 준다. 단순히 cudaMallocHost로 구현하면 기본값과 성능이 같다. 고정 메모리 풀, 대형 페이지, 병렬 프리폴팅 같은 처리를 넣어야 이득이 난다.
  • 그림 7·8은 인자 비영(nonzero) 원소가 180억~360억 개인 행렬에서 하이브리드 메모리 사용과 사용자 고정 메모리 처리기의 가속을 보여 준다. 대형 페이지·병렬 프리폴팅을 구현한 샘플은 CUDA library samples에 있다(배수 값은 확인하지 못함).

출처 1 · Pinned memory handler: Optimized data transfers; Figure 7·8 캡션

해석

본문은 메모리 절감 근거를 'Figure 2'라고 적었지만 해당 그림은 Figure 6이다. 편집상 오류로 보이며 수치 자체를 의심할 근거는 아니다.

투자 관점에서는 양면이 있다. 한 작업에 필요한 GPU 수가 줄면 도입 문턱이 낮아져 CPU 해법에서 넘어오는 사용자가 늘 수 있다. 반대로 이미 GPU로 넘어온 작업은 작업당 GPU 수가 줄 수 있다. 글은 어느 쪽이 큰지 판단할 자료를 주지 않는다. 고정 메모리 처리기도 사용자가 직접 할당기를 짜야 효과가 나므로, 이득은 상용 소프트웨어 회사처럼 통합 역량이 있는 쪽에 먼저 돌아갈 가능성이 크다(확신 낮음).

기호 분해는 2.21배 빨라졌지만 그 개선만으로 줄어드는 끝단 시간은 1.1~1.2배(추정)

사실
  • 1.0의 GPU 기호 분해는 B200과 H100 모두에서 0.8.0보다 기하평균 2.21배 빠르다.
  • 비교 범위는 B200에서 약 400개 행렬·구성(행 수 80~1억 3,030만), H100에서 약 250개(행 수 120~2,290만)다.
  • 기호 분해 시간만 바꾸고 재정렬·수치 분해·해법은 0.8.0 값으로 둔 추정 끝단 가속은 B200 1.18배, H100 1.14배(기하평균)다.
  • 0.8.0의 하이브리드 실행 모드로 기호 분해를 호스트에서 돌릴 수 있다. 작은 행렬은 장치 실행·전송 부담을 줄이고, 큰 행렬은 분석 단계의 최대 장치 메모리를 낮춰 장치 메모리를 넘는 문제도 분석할 수 있게 한다.
  • 하이브리드 메모리 모드가 꺼져 있으면 수치 분해·해법의 위치는 내부 휴리스틱이 행렬 구조로 정한다. 하이브리드 실행 모드를 켜도 이 단계들을 호스트로 강제하지 않는다.

출처 1 · Symbolic factorization improvements; Table 3 각주

계산

0.8.0에서 기호 분해가 끝단 시간에서 차지한 비중을 거꾸로 추정하면 B200 약 28%, H100 약 22%다. 기하평균끼리 단순 결합한 근사치다. 4분의 1 안팎을 차지하던 단계를 절반 이하로 줄인 셈이므로, 기호 분해 개선의 효과는 이 단계가 병목이던 작업에서만 크게 드러난다.

해석

추정 1.18배·1.14배는 기호 분해 개선만 떼어 본 값이다. 재정렬·수치 분해·해법은 0.8.0 값으로 고정돼 있다. 1.0에 들어간 다른 표적 최적화의 효과는 빠져 있으므로, 이 값을 1.0 전체의 끝단 개선 폭으로 읽으면 안 된다.

위 역산대로 0.8.0에서 기호 분해가 끝단 시간의 20~30% 수준이었다면, 나머지 70~80%는 재정렬·수치 분해·해법이 차지했다는 뜻이다. 기호 분해 가속만으로 끝단 시간이 크게 줄기는 어렵다. 1.0 전체가 0.8.0보다 끝단에서 얼마나 빨라졌는지는 글에 없으므로, 1.0을 '다시 한번 크게 빨라진 버전'으로 볼 근거도 이 글에는 없다(확신 중간).

근거는 어디서 왔나

사실
  • 성능 근거는 반도체·기계 모델링 애플리케이션에서 내보낸 행렬로 NVIDIA가 직접 돌린 벤치마크다. 비교 대상 MKL 버전과 GPU·CPU 모델은 밝혔다.
  • 정확도 근거는 공개된 SuiteSparse 행렬 모음과 우변이 모두 1인 벡터로 계산한 상대 잔차·NRBE다. 섭동 피벗 수는 분해 뒤 CUDSS_DATA_NPIVOTS로 얻는다.
  • 글쓴이 네 명은 모두 NVIDIA 소속이다. 수학 라이브러리 수석 제품 관리자(전 Google TPU 컴파일러), 희소 해법 팀 엔지니어링 관리자(전 MathWorks), cuDSS 엔지니어(전 Intel MKL 희소 기능 담당), CAE·EDA·CFD 담당 개발 기술 엔지니어(전 Lawrence Livermore 연구원)다.

비판적으로 다시 읽기

해석
  • 말하는 자리: 글쓴이 전원이 NVIDIA 제품·엔지니어링 조직이고, 글은 'Download cuDSS'로 끝나는 제품 홍보 글이다. 비교 대상 MKL은 경쟁사 Intel의 라이브러리다. 다만 글쓴이 중 한 명이 MKL 희소 기능 출신이라 기준선 설정이 허술할 가능성은 낮다고 본다.
  • 선택된 표본: 성능은 기하평균, 정확도는 '최대' 개선, 표 2는 '개선되는 행렬'만 보여 준다. 매칭이 정확도를 떨어뜨리거나 채움을 늘린 사례의 빈도와 크기는 없다.
  • 끝단 수치 부재: 단계별 가속만 있고 실제 시뮬레이션 한 번의 시간 단축이 없다. 유일한 끝단 수치(1.18배·1.14배)도 추정치다.
  • 버전 귀속: 약 30% 메모리 절감의 대부분은 0.8.0 성과이고 MKL 대비 가속도 여러 버전에 걸쳐 쌓인 것이다. '1.0이 가져온 것'과 '1.0까지 쌓인 것'이 섞여 있다.
  • 편집 오류: 메모리 그림 번호가 다르다(본문 Figure 2, 실제 Figure 6). 비대칭 행렬용 표 2의 캡션도 표 1과 똑같이 Bunch-Kaufman을 언급한다. 결론을 바꾸지는 않지만 수치를 인용할 때 주의가 필요하다.
  • 가격·라이선스·채택 고객 정보가 없어 상용 소프트웨어 회사들이 실제로 통합했는지는 이 글로 알 수 없다.

투자자 관점의 정리

해석
  • 확인된 것: NVIDIA는 CAE·EDA의 핵심 계산 단계인 희소 직접 해법을 GPU로 옮기는 소프트웨어를 '상용 배포 가능' 수준으로 내놓았다. 정확도(대칭 부정치)와 메모리(CPU DRAM 활용)라는 두 가지 채택 장벽을 기본 기능으로 다뤘다. 확신 중간.
  • 새로 나온 것: 1.0의 실질 변화는 성능보다 기본값과 운용성이다. 글이 내놓은 끝단 수치는 기호 분해 개선만 떼어 본 추정 1.18배(B200)·1.14배(H100)뿐이다. 1.0 전체가 0.8.0보다 끝단에서 얼마나 빨라졌는지는 제시되지 않았다. 시장이 '1.0 = 큰 도약'으로 받아들인다면 이 글에는 그 근거가 없다. 확신 중간.
  • 답하지 않은 것: 끝단 시간 단축, CPU 기준선 조건, 상용 소프트웨어 통합과 고객 사례, 단일 GPU 해법이 작업당 GPU 수요에 주는 순효과. 실적 추정이나 밸류에이션 전제를 바꿀 정보는 이 글에 없다.
  • 실적·위험에 주는 뜻: NVIDIA 데이터센터 매출에서 CAE·EDA 시뮬레이션은 AI에 비하면 작은 갈래로 보이며, 이 글은 그 비중을 다루지 않는다. 따라서 숫자보다는 'CUDA-X 라이브러리로 CPU 작업을 GPU로 옮기는 전략'이 계속 진행 중이라는 정성적 근거로 쓴다.
  • NVIDIA — 약한 호재, 확신 중간. 근거: CPU 대비 단계별 가속, 정확도 기본값 개선, 단일 GPU 해법으로 CAE·EDA에서 GPU 도입 문턱이 낮아짐. 판정을 바꾸는 조건: 상용 시뮬레이션 소프트웨어의 통합 발표나 고객 끝단 사례가 나오면 강도를 올린다. 하이브리드 모드로 작업당 GPU 수가 줄었다는 사용자 사례가 쌓이면 낮춘다.
  • Intel — 약한 악재, 확신 낮음. 근거: MKL·Xeon이 공식 비교 기준으로 쓰여 CPU 희소 해법이 대체 대상으로 지목됨. 다만 하이브리드 모드는 CPU 메모리(512GB~2TB)와 호스트 스레드를 적극 쓰고, 재정렬은 항상 호스트에서 돈다. CPU가 노드에서 빠지는 구조가 아니다. 판정을 바꾸는 조건: 끝단 비교에서 GPU 우위가 단계별 배수보다 훨씬 작게 나오면 중립.
  • Synopsys — 중립, 근거 부족. 근거: PrimeSim에서 행렬을 내보냈다는 언급뿐이고 협업·통합·매출 영향을 말하지 않음. 판정을 바꾸는 조건: PrimeSim의 cuDSS 통합과 고객 효과가 별도 자료로 확인되면 재검토.
  • 그 밖의 CAE·EDA 소프트웨어 회사와 전력망 해석·최적화 소프트웨어 회사는 원문에 이름이 없어 판정하지 않는다.
  • 다음에 확인할 지표: 상용 회로 시뮬레이션·CAE 제품의 cuDSS 채택 발표와 끝단 시간 비교, 고정 메모리 처리기 샘플을 쓴 대형 VLSI 사례의 실제 가속, 다음 버전에서 다중 GPU·Vera Rubin 기준 수치가 나오는지.
