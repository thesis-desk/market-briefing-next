NVIDIA Technical Blog : RTX Blackwell의 NVFP4 어텐션은 레지스터 재활용으로 텐서코어 빈틈을 메워 빨라진다

해석 워크스테이션·서버용 RTX Blackwell(SM120)에서 NVFP4 어텐션의 텐서코어 공백을 줄이는 스케줄링 기법을 소개한 글이다. 커널 최대 1.64배, 종단 지연 최대 15.34% 단축이라는 수치는 페이지 상단의 AI 생성 요약에만 글로 나오고 본문 표는 확인하지 못했다. 출력 품질 수치도 없다. 기술적으로는 타당하지만 종목에 미치는 영향은 작다.

주장 한 줄

사실

RTX Blackwell(SM120)에서는 데이터센터용 FlashAttention3·4의 파이프라인을 그대로 쓸 수 없다. 대신 softmax 결과를 NVFP4로 묶은 직후 스코어 레지스터를 다음 타일의 QK 계산에 다시 쓰면, 두 번째 스코어 버퍼를 두지 않고도 텐서코어 유휴 시간을 줄여 NVFP4 어텐션을 가속할 수 있다는 주장이다. 핵심 코드는 FlashInfer main 브랜치에 병합됐다.

출처 1 · 도입부, Get started accelerating NVFP4 attention

글쓴이는 NVIDIA의 딥러닝 알고리즘 엔지니어로, NVIDIA Cosmos를 포함한 월드 파운데이션 모델의 커널 성능과 추론 최적화를 맡고 있다. 실측 수치는 월드 모델 서빙 플랫폼 Reactor가 제공했다.

출처 1 · About the Authors, Acknowledgments

RTX Blackwell의 병목은 softmax가 아니라 MMA라서 NVFP4가 먹힌다

사실
  • RTX Blackwell은 데이터센터용 Blackwell보다 BF16 행렬곱 처리량이 낮다. 그래서 BF16 영상 생성 모델의 어텐션은 주로 MMA에서 막힌다. 데이터센터 Blackwell의 순방향 어텐션에서는 softmax가 주요 병목이고, FlashAttention4는 파이프라이닝과 exp2 에뮬레이션으로 이를 풀려고 한다.
  • SM120은 텐서코어 구조가 달라서 Hopper·데이터센터 Blackwell용 FlashAttention3·4 파이프라인을 직접 적용할 수 없다.
  • NVFP4는 TFLOP/s가 더 높아서 MMA에서 막히는 RTX 쪽 어텐션의 처리량을 끌어올릴 여지가 있다. 다만 softmax, 데이터 이동, 중간 저장 사이의 의존성 때문에 텐서코어가 놀 수 있다.

출처 1 · 도입부, Improving throughput with NVFP4

  • SageAttention3는 SM120 전용 네이티브 NVFP4 어텐션이다. QK와 PV를 모두 NVFP4로 수행한다.
  • SageAttention3의 핵심 기법은 P(softmax 출력)의 2단계 스케일링이다. softmax 출력은 [0, 1] 구간에 몰려 있어서 NVFP4의 동적 범위를 다 쓰지 못하고 정확도가 떨어진다. 그래서 값을 먼저 정규화해 동적 범위를 채운 뒤 양자화한다. NVFP4 양자화 결과는 NVFP4 데이터 텐서와 FP8 스케일 텐서 두 개다.

출처 1 · How SageAttention3 accelerates attention using NVFP4

해석

FlashAttention4가 데이터센터 칩에서 softmax 병목을 다루는 것과 정반대 상황이다. RTX 계열은 BF16 연산이 약해서 저정밀 포맷의 효과가 데이터센터보다 크게 나오는 구조로 보인다. 같은 Blackwell 세대라도 최적화 경로가 제품군별로 갈린다는 점이 이 글이 전하는 정보다.

원래 SageAttention3는 타일마다 직렬로 돌아 텐서코어가 쉰다

사실
  • CTA는 워프 12개로 구성된다(프로듀서 4, 컨슈머 8). 컨슈머는 N128 타일마다 QK → 마스킹·온라인 softmax·확률 양자화 → PV를 차례로 실행한다. 타일 안에서 겹치는 작업이 없다.
  • TMA 로드는 128×128 형상에 묶여 있다. 형상을 다 쓰지 않으면 대역폭이 낭비된다.
  • RTX Blackwell의 NVFP4 MMA 명령(mma.sync…m16n8k64)은 k=64로 고정이다. 따라서 k=128을 덮으려면 명령 두 개를 연달아 내야 한다. MMA가 동기 실행이라서 컨슈머 워프는 MMA가 끝날 때까지 기다린 뒤에야 softmax와 양자화로 넘어간다.
  • 그 결과 softmax·스케일링·양자화가 도는 동안 텐서코어에 배정된 작업이 없어 MMA 활동에 큰 공백이 생긴다.

출처 1 · SageAttention3 cooperative thread array stable state design

레지스터가 95% 차 있어 버퍼를 늘리지 않고 N64 두 칸을 돌려 쓴다

사실

레지스터는 프로듀서 워프가 3,072개, 컨슈머 워프가 59,392개를 써서 합계 62,464개다. 이는 SM 레지스터 용량의 약 95.3%로, 현재 타일을 처리하면서 스코어 타일을 하나 더 들고 있을 여유가 거의 없다.

출처 1 · Register constraints

  • 워프 구성(프로듀서 4·컨슈머 8)과 N128 K/V 타일 전체 로드는 그대로 둔다. 바뀌는 것은 컨슈머가 스코어를 계산하고 저장하는 방식이다.
  • N128 스코어 타일을 N64 두 칸(열 0–64, 64–128)으로 나누고 각각 별도 레지스터 슬롯에 둔다.
  • 한쪽 절반을 지수화하고 NVFP4로 양자화하면 그 슬롯은 더 이상 쓰이지 않는다. 그 레지스터로 다음 타일의 해당 절반 QK를 바로 계산한 뒤 현재 타일의 PV를 누적한다. 다음 타일의 QK가 현재 타일의 남은 softmax·양자화·PV와 교차 실행된다.
  • 온라인 softmax 상태(최댓값·합)는 두 절반을 소비하기 전에 N128 타일 전체에 대해 한 번에 갱신한다. 마지막 타일은 덮어쓸 다음 타일이 없으므로 QK 없이 소진하고, 마지막에 합으로 나눠 BF16으로 저장한다.

출처 1 · Optimized CTA design

해석

요점은 이중 버퍼링의 효과를 버퍼 하나 분량의 레지스터로 얻는 것이다. 정규화에 필요한 통계(최댓값·합)는 N128 전체로 먼저 확정하고, 지수화·양자화·PV만 절반 단위로 쪼갰다. 원래 설계와 같은 결과를 내도록 짠 것으로 보인다. 다만 확률 양자화를 N64 단위로 나눠 해도 결과가 같은지는 원문으로 알 수 없다(확신 낮음). 원문은 두 설계의 출력을 직접 비교한 결과를 제시하지 않는다.

성과는 커널 최대 1.64배, 종단 지연 최대 15.34% 단축(AI 요약에만 글로 나온 수치)

사실
  • 커널: RTX PRO 6000 Blackwell에서 NVFP4 어텐션 커널 지연이 최대 1.64배 개선됐다.
  • 종단: Reactor의 프로덕션 서빙 스택에서 LongLive, Helios, OmniDreams, Cosmos 3 Nano 워크로드의 종단 추론 지연이 최대 15.34% 줄었다. 비교 기준은 BF16 어텐션이다(Table 2 캡션 기준. 영상 청크·행동 예측의 기준선은 cuDNN BF16 어텐션).
  • 두 수치는 페이지 상단의 AI 생성 요약(NVIDIA Nemotron)에 나온다. 본문은 결과를 Table 1·2 그림으로만 싣고 글로는 'tremendous speedups'라고만 적었다. 이 리포트는 표 안의 수치를 확인하지 못했다.

출처 1 · AI-Generated Summary, Table 1·2 캡션

  • 시험 장비: RTX PRO 6000 Blackwell Server Edition(96GB, SM120). Reactor가 측정했다.
  • 커널 비교: 원래 커널과 최적화 커널에 같은 Q/K/V 입력, 같은 패킹 텐서, 같은 log-sum-exp 설정을 썼다. 배치 1, 헤드 24개, 헤드 차원 128, 쿼리·키 길이는 같다. 7,040토큰 입력만 LongLive에서 캡처했고 나머지는 합성 입력이다. Q/K/V 양자화와 출력 stride 복원 시간은 빠졌다. 구현마다 새 프로세스 3개를 띄우고 실행 순서를 번갈아 바꿨으며, 사전 워밍업 후 CUDA 이벤트로 반복 측정했다.
  • 종단 비교: 일부 어텐션 연산만 NVFP4이고 나머지 어텐션과 모델 가중치는 BF16이다. 영상 청크·행동 예측의 기준선은 cuDNN BF16 어텐션이다. 양자화, 레이아웃 변환, CPU 프레임·행동 출력 디코딩은 포함했고 모델 로딩, 워밍업, 네트워크, 대기열, 클라이언트 페이싱은 뺐다.
  • 장시간 생성: LongLive와 Helios는 eager 실행으로 독립 프로세스 3회의 중앙값을 냈다. OmniDreams는 비교 대상·시나리오마다 프로세스 1회다. 단축률은 반올림 전 측정값으로 계산했다.

출처 1 · NVFP4 attention kernel integration latency results

해석

두 수치는 기준선이 다르다. 1.64배는 최적화 전후 NVFP4 커널끼리의 비교이고, 15.34%는 BF16 어텐션 대비 최적화된 NVFP4 어텐션의 종단 효과다. 따라서 15.34%에는 BF16→NVFP4 전환 효과와 레지스터 재활용 효과가 섞여 있다. 이 글의 기법만으로 얻은 종단 개선이 얼마인지는 글로 확인한 범위에서는 알 수 없다. BF16 대비 NVFP4 어텐션 구간의 속도 향상도 글에 나오지 않아 종단 시간 중 어텐션 비중을 역산할 수도 없다.

근거는 어디서 왔나

해석
  • 독자가 검증할 수 있는 근거: 알고리즘 설명, 의사코드, 레지스터 수, MMA 명령 형상은 공개 PTX와 FlashInfer main 브랜치의 병합 코드로 확인할 수 있다.
  • Reactor만 가진 근거: 종단 수치는 Reactor 프로덕션 스택에서 쟀다. 모델 구성(어느 어텐션 연산이 NVFP4인지)은 표에 있다고 했지만 외부에서 재현하기는 어렵다.
  • 커널 수치는 7,040토큰 한 건만 실제 입력이고 나머지는 합성 입력이다. 측정 절차(새 프로세스, 순서 교차, 워밍업)는 꼼꼼하게 밝혔다.

글이 지목한 수혜 대상

사실
  • NVIDIA RTX PRO 6000 Blackwell(SM120): 이 기법의 대상 하드웨어다.
  • Reactor: 실시간 영상·로보틱스·월드 모델 배포 플랫폼으로, 커널을 프로덕션에 넣어 실제 고객 트래픽에 쓰고 있다.
  • FlashInfer 사용자: 핵심 최적화가 main 브랜치에 병합됐다. 원문은 SM120 NVFP4 어텐션 API를 붙여 BF16 기준선과 지연·출력 품질을 비교해 보라고 권한다.
  • 대상 워크로드: LongLive, Helios, OmniDreams, Cosmos 3 Nano 같은 월드 모델·영상 생성 추론.

출처 1 · 도입부, Get started accelerating NVFP4 attention

비판적으로 다시 읽기

해석
  • 품질 수치가 없다. 원문은 softmax 출력이 [0, 1]에 몰려 NVFP4로 그대로 양자화하면 정확도가 떨어진다고 적고, SageAttention3의 2단계 스케일링을 그 대응책으로 소개한다. 그러나 이 대응이 영상 품질을 얼마나 지키는지는 보여 주지 않는다. 독자에게는 BF16과 출력 품질을 비교하라고 권하면서 글 자체에는 품질 비교가 없다. 1.64배·15.34%는 품질 손실이 허용 범위라는 전제 위에서만 의미가 있다.
  • '최대'라는 표현이 수치를 받친다. 표를 읽지 못해서 워크로드·카메라 시나리오(idle·moving)별로 단축 폭이 얼마나 퍼져 있는지 모른다. 본문에서 개선 폭이 작은 경우를 언급하지 않는다.
  • OmniDreams는 프로세스 1회 측정이어서 변동을 걸러내지 못했다. LongLive·Helios는 eager 실행 기준이다. 컴파일·그래프 실행을 쓰는 실제 배포에서도 같은 비율이 나올지는 원문으로 판단할 수 없다(확신 낮음).
  • 이해관계가 있다. 글쓴이는 NVIDIA 직원이고, 글은 RTX PRO 6000을 월드 모델 추론 장비로 내세운다. 실측은 Reactor가 제공했고, 글은 Reactor의 프로덕션 도입 과정을 다룬 별도 글로 독자를 안내한다. 기법 자체는 공개 코드로 검증할 수 있어 신뢰를 떨어뜨리는 수준은 아니다.
  • 비교 대상이 좁다. 커널 비교는 원래 SageAttention3 대비이고 종단 기준선은 cuDNN BF16 어텐션이다. FP8 어텐션 같은 중간 대안이나 다른 회사 가속기와의 비교는 없다.

투자자 관점의 정리

해석
  • 확인된 것: RTX Blackwell은 BF16 MMA가 병목이어서 NVFP4 같은 저정밀 포맷의 효과가 데이터센터 칩보다 직접적으로 나타난다. 그 효과를 실제로 꺼내려면 레지스터 수준의 스케줄링이 필요하고, 그 작업이 오픈소스(FlashInfer)로 공개됐다. 확신 중간.
  • 새로 나온 것: 월드 모델 서빙 업체가 RTX PRO 6000을 프로덕션 추론에 쓰고 있고, 어텐션을 BF16에서 NVFP4로 바꾸는 소프트웨어 변경만으로 종단 지연을 최대 15%대 줄였다. 다만 이 수치는 AI 요약에만 글로 나오고 표는 확인하지 못했다. 또 BF16 대비 수치여서 그중 레지스터 재활용 기법의 몫이 얼마인지는 알 수 없다. 확신 중간.
  • 답하지 않은 것: NVFP4 어텐션의 출력 품질 손실, 워크로드별 개선 폭의 분포, Reactor의 배포 규모(GPU 수·트래픽)가 빠졌다. 배포 규모가 없으니 하드웨어 수요로 환산할 근거가 없다.
  • NVIDIA: 중립, 약한 호재 쪽(확신 낮음). 데이터센터 GPU보다 싼 RTX PRO 계열을 월드 모델·영상 생성 추론에 쓰게 하는 소프트웨어 생태계가 두꺼워지는 신호다. 다만 블로그 한 편과 한 고객 사례로는 실적 추정이나 밸류에이션 전제를 바꿀 수 없다. RTX PRO 계열의 데이터센터 추론 채택이 공시나 고객 사례에서 반복 확인되면 판정을 올린다.
  • Reactor는 비상장이라 종목 판정 대상이 아니다. 경쟁 가속기 업체, 메모리·장비 등 다른 종목은 원문에 근거가 없어 판정하지 않는다. 다음 확인 지점은 세 가지다. FlashInfer의 SM120 NVFP4 경로를 쓰는 다른 서빙 업체가 나오는지, BF16 대비 품질 비교 결과가 공개되는지, Reactor 글에 배포 규모가 있는지.
