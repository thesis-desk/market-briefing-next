Microsoft Ignite 2026 : 마이크로소프트가 기업 AI 지출의 배분자 자리를 노린다, 프론티어 랩에는 값 압박

해석 이번 Ignite의 무게중심은 새 모델이나 GPU가 아니다. 마이크로소프트는 자사 라우터와 소형·특화 모델이 작업마다 어느 모델을 얼마나 쓸지 정하게 하고, 경쟁사 에이전트까지 자사 관리 층 아래에 두는 구도를 내놓았다. 마이크로소프트의 마진에는 호재이고, Copilot 경로로 팔리는 프론티어 모델의 값에는 악재다. 다만 판단을 확정할 수치(라우팅 비율, 과금 단가, 좌석 수)는 공개되지 않았다.

핵심

해석

이번 Ignite로 바꿔야 할 판단은 마이크로소프트의 자리다. 마이크로소프트는 프론티어 모델을 유통하는 채널에서, 작업마다 어느 모델에 얼마를 쓸지 정하고 그 지출을 관리하는 배분자로 옮겨 가고 있다. 프론티어 랩에는 값 압박, 마이크로소프트에는 마진 개선 쪽이다. 하드웨어 쪽 변화(온프렘·PC 추론)는 방향은 분명하지만 물량이 아직 보이지 않는다.

  • 경쟁 축이 성능에서 작업당 비용으로 옮겨 갔다 — Copilot 트래픽의 모델 배분을 마이크로소프트의 라우터가 정한다(확신 중간)
  • 마이크로소프트는 앞단을 지키면서 맥락 층을 경쟁 비서에 판다 — 앞단을 잃어도 통행료를 남기는 양다리다(확신 중간)
  • 경쟁사 에이전트까지 자사 관리 층 아래 둔다 — 보안·백업 협력사는 신호 공급자나 기능 중복 상대로 밀린다(확신 낮음~중간)
  • 추론 실행 위치가 PC·온프렘으로 넓어졌다 — 엔비디아·델이 양쪽을 다 잡았지만 물량은 아직 보이지 않는다(확신 낮음)

경쟁 축이 성능에서 작업당 비용으로 옮겨 갔다 — Copilot 트래픽의 모델 배분을 마이크로소프트의 라우터가 정한다

사실
  • Copilot의 Auto는 작업에 맞춰 모델과 추론 강도를 고르는 라우터다. Copilot에서는 Microsoft-Decision-1.1이 요청을 Copilot과 Cowork 가운데 어디서 처리할지 정하고, Cowork의 Auto에서는 작업을 쪼개 부분마다 모델을 붙인 뒤 Decision-1.1이 부분별 추론 강도를 정한다(Cowork 쪽은 Frontier 고객 대상).
  • Microsoft-Decision-1.1은 Google의 Gemma 4 26B A4B를 바탕으로 만든 결정 전용 모델로 GA다. Artificial Analysis Decision Index v2.1에서 68점(전작 대비 +6)으로 Gemini-Decision-1, GPT-6 Luna (Decisions)를 앞섰고, 전작과 같은 가격에 두 배 넘게 빠르다. Foundry 외에 OpenRouter·Vercel에서도 판다.
  • Foundry 모델 라우터는 Foundry 상위 50개 모델로 풀을 넓혔고, Foundry의 모델 수는 11,000개가 넘는다. MAI-Code-2와 MAI-Code-2-Flash는 GitHub에서 GA다.
  • Microsoft IQ의 business plugins는 불필요한 맥락을 줄여 결과 품질을 높이고 토큰 비용을 낮추는 것을 목표로 내걸었다.

  • 직원은 조직 정책 범위 안에서 OpenAI·Anthropic 모델을 직접 고를 수도 있다.
  • 과금은 사용자당 구독과, 가장 어려운 작업에 강력한 모델을 쓰는 사용량 기반 소비의 두 갈래다. 회사는 앞으로 더 많은 기능을 구독 라이선스 안으로 옮기겠다고 했다.

출처 8 · 5. MAI

해석

근거를 한데 놓으면 구조가 보인다. Andreou의 말대로 Copilot 질의의 90% 이상이 Auto를 지난다. Auto는 마이크로소프트의 라우터이고, 그 안의 판단 일부(요청을 Copilot과 Cowork 가운데 어디서 처리할지, Cowork에서 부분 작업별 추론 강도)는 Gemma 기반 자사 결정 모델이 내린다. 그 위에 자사 MAI 모델과 오픈 모델 맞춤 학습(Programmed Training)이 깔린다. 회사가 내놓은 비교는 대부분 OpenAI·Anthropic·Google 모델 대비 성능·비용으로 짜였다. 프론티어 모델은 사라지지 않지만 '가장 어려운 작업'의 사용량 과금 칸으로 밀려난다. 어떤 작업이 그 칸에 들어갈지는 마이크로소프트의 라우터가 정한다.

이전 판단과 달라지는 점: Copilot은 OpenAI·Anthropic 모델이 기업 사용자에게 닿는 경로 가운데 하나다(그 규모는 원문에 없다). 그 경로의 주인이 라우팅을 자기 라우터와 결정 모델로 쥐었다. 프론티어 랩의 기업 몫이 값뿐 아니라 배분(물량)으로도 깎일 수 있는 통로가 생겼다는 뜻이다. 크기는 가늠할 수 없다. 라우팅된 질의 가운데 프론티어 모델로 가는 비율도, Copilot 경로가 프론티어 랩 기업 매출에서 차지하는 몫도 공개되지 않았다. 시점은 Cowork의 Decision-1.1 라우팅이 아직 Frontier 단계라 본격 효과는 2027년 이후로 본다.

누구에게 무엇인가: 마이크로소프트는 질의당 원가를 낮추면서 구독 단가를 유지할 수 있어 Copilot 마진에 유리하다. OpenAI·Anthropic은 Copilot 경로의 물량과 단가가 함께 눌릴 위험을 진다. 엔비디아는 Nemotron이 Foundry 맞춤 학습의 기본 재료로 자리 잡는 쪽에서 소폭 득을 본다. Gemma가 Microsoft 결정 모델의 바탕이 된 것은 알파벳에 상징적이나 돈의 흐름은 작다.

이 주장이 틀리는 경우: 비용 비교는 모두 회사가 고른 벤치마크이고, MAI Code 2 수치는 2차 블로그가 옮긴 값이며 프로모션 가격이 섞였다. GigaOm 비교의 조건도 원문에 없다. 사용자가 OpenAI·Anthropic 모델을 직접 고를 수 있고, 어려운 작업일수록 사용량 과금으로 프론티어 모델을 더 쓸 수 있어 지출 총액이 오히려 늘 수도 있다. 라우팅 비율과 모델별 지출이 나오기 전까지는 방향만 확인된 상태다.

마이크로소프트는 앞단을 지키면서 맥락 층을 경쟁 비서에 판다 — 앞단을 잃어도 통행료를 남기는 양다리다

출처 11 · Differentiating from what Anthropic and OpenAI are doing

사실
  • Office in Copilot(Word·Excel·PowerPoint)은 GA다.
  • Fabric IQ는 ChatGPT·Claude용 커넥터를 프리뷰로 내놓아, 두 비서 안에서 Power BI 시맨틱 모델의 지표로 답하게 한다. Work IQ는 OpenAI·Anthropic 플랫폼과의 연동을 계획했다(Anthropic은 '곧').
  • Salesforce in Copilot(판매 스킬 38개 이상)은 프리뷰, Salesforce Data 360과 Fabric OneLake 사이의 Zero Copy Data Federation은 GA다.
  • 같은 날 Dynamics 365 Activate는 Salesforce에서 Dynamics 365로 옮기는 CRM 이전 기능을 GA로 냈고, 주력 유지보수 종료가 다가오는 SAP ECC 환경을 분석해 Dynamics 365로 옮기는 ERP 이전 기능의 롤아웃을 시작했다.

출처 1 · Fabric IQ; Work IQ; Microsoft, Salesforce announce Salesforce in Copilot, Teams and Fabric; Microsoft expands Dynamics 365 Activate

  • Dynamics 365 in Copilot 플러그인은 판매·서비스·재무운영 스킬 100개 이상을 Copilot에 넣는다.

  • Office in Copilot 기능은 사용량 과금 없이 Copilot 구독 라이선스에 포함된다(회사 주장).

출처 9 · Redesigning how the business works; Scale with confidence

해석

두 갈래가 동시에 나왔다는 점이 핵심이다. 앞단에서는 '진짜 Office'를 Copilot에 넣고 추가 과금을 없애 OpenAI·Anthropic의 문서 기능과 정면으로 붙었다. 뒤에서는 Work IQ·Fabric IQ를 바로 그 경쟁 비서에 연결한다. Copilot이 앞단 싸움에서 지더라도 기업 데이터의 의미·권한 층(Fabric·Power BI·M365)이 남아 있으면 마이크로소프트는 소비 매출을 받는다는 계산으로 읽힌다.

같은 구도가 업무 시스템에도 걸린다. Salesforce는 Copilot 안의 플러그인이자 Activate의 이전 대상이고, SAP ECC는 유지보수 종료를 계기로 한 이전 대상으로 명시됐다. 기록 시스템(SoR) 업체가 Copilot의 플러그인 자리로 내려가는 흐름이다. 크기와 시점은 원문에 수치가 없어 가늠할 수 없다. 이전 기능은 롤아웃 초기다.

누구에게 무엇인가: 마이크로소프트는 좌석 방어와 소비 매출 양쪽에 걸쳐 하방이 얕아진다. SAP는 ECC 이전 수요를 마이크로소프트가 에이전트 도구로 직접 겨냥해 약한 악재다. Salesforce는 Copilot 유통과 데이터 연동을 얻는 대신 이전 표적이 되어 엇갈린다. OpenAI·Anthropic은 기업 맥락에 접근할 길을 얻지만 그 맥락의 관문은 마이크로소프트가 쥔다.

이 주장이 틀리는 경우: 커넥터의 과금 방식이 공개되지 않아 '통행료'가 실제 매출이 될지 모른다. Thurrott는 Office 기능이 결국 어느 AI 비서에서나 쓰이게 되어 Office·M365에 부정적 변화가 올 수 있다고 본다(매체의 평가). Today는 블로그에서 Home 안의 기능으로 소개됐지만 세션에서는 '곧'이라 했고, Copilot Code GA도 Book of News는 12월, 블로그는 '몇 주 안'이라 적어 일정 표현이 출처마다 다르다. 좌석 수·이전 건수 같은 결과 지표가 없다.

경쟁사 에이전트까지 자사 관리 층 아래 둔다 — 보안·백업 협력사는 신호 공급자나 기능 중복 상대로 밀린다

사실
  • Dynamic Agent Risk(프리뷰)는 Check Point, Cyera, Darktrace, Zenity의 에이전트 보안 신호를 Microsoft Sentinel로 받아 증거로 쓰고, 통합 위험도(낮음·중간·높음)는 마이크로소프트가 계산한다. 협력사는 데이터 출처로 표시된다.
  • Defender의 로컬 에이전트 런타임 보호는 Windows에서 Claude Code, Claude Desktop, GitHub Copilot CLI 등(에이전트 내장 방식)과 OpenClaw, Ollama Desktop, ChatGPT Desktop 등(네트워크 방식)에 GA이며 Defender for Endpoint P2 고객용이다.
  • Edge for Business는 마이크로소프트·타사 에이전트가 브라우저 작업을 할 때 Edge 사용을 IT가 강제하게 하는 기능을 프리뷰로 냈다. Entra는 Claude Code·GitHub Copilot CLI 같은 로컬 에이전트에 Agent ID를 자동 부여한다(프리뷰).

출처 10 · Observations

해석

마이크로소프트는 자사 에이전트만이 아니라 Claude Code·ChatGPT·OpenClaw 같은 경쟁 에이전트까지 신원(Entra), 단말(Intune·Defender), 브라우저(Edge), 데이터(Purview), 위험 점수(Agent 365)로 묶었다. 협력 보안사는 Sentinel로 신호를 넣는 공급자가 되고 최종 판정은 마이크로소프트가 내린다. 기본 지표는 무료로 풀고 위험·보안 기능은 Agent 365·ME7·Defender P2 라이선스에 둔 것은 상위 라이선스로 끌어올리는 깔때기 설계로 읽힌다.

백업은 범위가 좁지만 겹침이 실제로 생겼다. Entra 백업·복구는 Cohesity가 같은 날 강조한 기능과 정면으로 겹치고, Cosmos DB·PostgreSQL 백업도 네이티브로 들어왔다. 크기는 가격과 채택 수치가 없어 가늠할 수 없다. 대부분 프리뷰라 시점은 2027년이다.

누구에게 무엇인가: 마이크로소프트 보안·관리 매출(상위 라이선스 전환)에 호재다. 에이전트 보안 전업사는 독자 판정 자리를 잃을 위험이 있다. 원문에 이름이 나온 협력사(Check Point·Cyera·Darktrace·Zenity) 가운데 이 리포트는 Check Point만 판정한다. Check Point는 협력사로 들어가 유통을 얻으니 중립이다. 백업 업체(Rubrik·Commvault 등)는 Entra·Azure 데이터베이스 영역에서 네이티브 기능과 겹쳐 약한 악재다.

이 주장이 틀리는 경우: 플랫폼 네이티브 백업은 보존 기간(30일)·범위가 좁아 규제·사이버 복원 요구가 큰 고객은 여전히 전문 업체를 쓸 수 있다. 협력사 신호 연동은 '계획된 흐름'이라 실제 운영 형태는 바뀔 수 있다. 근거의 상당 부분이 프리뷰 기능이고, 평가 일부는 매체·정리 글의 해석이다.

추론 실행 위치가 PC·온프렘으로 넓어졌다 — 엔비디아·델이 양쪽을 다 잡았지만 물량은 아직 보이지 않는다

사실
  • Windows Server 2028(프리뷰)은 Windows ML·Foundry Local·vLLM·llama.cpp 기반 기업 추론을 지원하고, 하드웨어로 AMD MI350P 가속기와 NVIDIA GB300 Grace Blackwell Ultra Desktop Superchip을 명시했다. 하이브리드 추론 기능은 제한된 고객의 조기 접근 단계다.
  • Windows 365 Cloud PC는 최대 32 vCPU·GPU 사양에서 로컬 AI 모델 실행을 GA로 지원한다.
  • Cobalt 200 VM(GA)은 에이전트가 모델 밖의 범용 CPU에서 많은 일을 한다는 전제로 설계됐고 Cobalt 100 대비 CPU 성능이 최대 50% 높다. 연말까지 24개 리전에 배치하며, Azure Database for PostgreSQL에서도 Intel·AMD x64 선택지 옆에 GA로 추가됐다.
  • Azure 절의 실리콘 발표는 Cobalt 200(CPU)뿐이고, 가속기로는 엔비디아·AMD 제품만 나온다.

출처 8 · 6. Toward an Era of Combining Local AI and Cloud AI

해석

클라우드·온프렘 서버·PC·엣지에서 같은 Foundry 경로로 같은 모델을 돌리는 소프트웨어 틀이 이번에 갖춰졌다. 하드웨어 이름을 이어 보면 엔비디아는 Azure(Vera Rubin), 온프렘 서버(RTX PRO 6000, GB300 데스크톱), PC(RTX Spark)에 모두 있다. 델은 RTX Spark 데스크톱과 AI Factory(Foundry Local) 양쪽에 있다. AMD는 Windows Server 2028 가속기 목록(MI350P)과 GitHub Copilot Fusion 로컬 모델 대상 하드웨어(Ryzen AI Max, 보도)에 이름을 올렸다.

에이전트 실행의 CPU 몫은 자체 Arm 칩 Cobalt로 가져가는 그림이다. Azure 안에서 에이전트용 범용 연산이 x86 대신 Cobalt로 갈 여지가 커졌다. 크기는 가늠할 수 없다. 어느 하드웨어에도 물량·가격이 없고, Vera Rubin VM도 가격·리전·GA 일자가 원문에 없다. 시점은 Windows Server 2028이 프리뷰·조기 접근 단계라 2027년 이후다.

누구에게 무엇인가: 엔비디아는 데이터센터 밖 추론 수요가 커져도 PC·워크스테이션·온프렘 GPU로 받아 내 약한 호재다. 델은 온프렘 AI Factory와 RTX Spark 데스크톱 양쪽에서 약한 호재다. AMD는 엇갈린다. 가속기 쪽에서는 Windows Server 2028의 MI350P로 발판을 얻었고, Azure 안 범용 CPU 몫은 Cobalt에 잠식된다. 인텔은 Azure 에이전트용 범용 연산에서 Cobalt에 밀리는 쪽이다. 로컬 실행이 토큰 과금을 피한다는 엔비디아의 주장은 t1의 프론티어 랩 값 압박과 같은 방향이다.

이 주장이 틀리는 경우: Thurrott는 Copilot의 로컬 모델 오프로딩이 아직 누구에게도 제공되지 않는다고 지적했다. 로컬 실행은 하드웨어 제약과 관리·모델 갱신 부담이 따른다(s8도 같은 단서를 달았다). 기업이 결국 클라우드 추론에 머물면 이 흐름은 데모 수준에 그친다. s12는 Vera Rubin VM 관련 일자가 문서마다 11월 12~19일로 다르고 일부 보도는 프리뷰로 적는다고 했다. Cobalt 50% 개선은 회사가 정한 조건의 비교다.
